How to use the challenge

Use this guide to understand the case, expected optimized cost, runtime readiness, evaluation scores, and agent trace.

1. Team / case

The student package only exposes the Team 1–5 workspaces available to that package. The instructor-only demo case is not part of this frontend.

The public case context is loaded independently from the evaluation token so you can inspect the assignment even before running an evaluation.

2. Scenario and expected optimized cost

Select a public development scenario. Its published Expected Optimized Cost is shown immediately in the metric row.

Use this target to check whether your system is converging toward a good operational plan. It is a cost benchmark, not a published reference plan.

3. Manager LLM

Select the LLM used as the Manager/orchestrator. PyTorch models, RAG, Skills, tools, simulator, and evaluator remain the same.

  • READY: provider key is configured.
  • KEY MISSING: configure that provider before running it.

4. Run AI Manager end-to-end

Runs the complete workflow:

LLM Manager → Skills → RAG → PyTorch → Tools → Structured Plan → Server Evaluation

The evaluation token must be valid when you run the scenario.

5. Runtime status badges

  • Data: assigned business case loaded.
  • RAG: team RAG configuration is present.
  • Knowledge: number of documents supplied by the Data API.
  • Skills: number of team Skill files.
  • model_a.pt2 / model_b.pt2: local trained PyTorch artifacts.
  • LLM badges: provider configuration state.

6. Main result cards

  • Feasibility: whether the plan satisfies hard operational constraints.
  • Service: realized service performance.
  • Total Cost: realized simulated operating cost.
  • Expected Optimized Cost: the public benchmark for the selected scenario.
  • RAG: expected organizational evidence retrieved.
  • Skills / Tools: procedural Skill/tool discipline and workflow quality.

7. Cost breakdown

After a run, compare realized total cost with the expected optimized cost. This panel also shows the cost gap, Cost Score, Operational Score, and individual cost components when returned by the evaluator.

8. Violations

Review simulator findings. Critical violations make the operational plan infeasible even if the numerical cost is low.

9. Evaluation breakdown

Explains the operational score, cost/service/feasibility contributions, RAG coverage, Skills/Tools usage, validation discipline, and efficiency diagnostics returned for the public scenario.

10. Agent tool trace

Review the Manager's tool calls in order to confirm that it actually used the intended architecture rather than producing an unsupported answer.

11. Recommended workflow

  1. Select your assigned team and a public scenario.
  2. Read the scenario and note the Expected Optimized Cost.
  3. Confirm RAG, Skills, models, and an LLM provider are ready.
  4. Run the AI Manager.
  5. Check feasibility and service first.
  6. Compare Total Cost with Expected Optimized Cost.
  7. Review Cost Score, cost gap, and cost components.
  8. Review RAG and Skills/Tools diagnostics.
  9. Inspect the tool trace and structured plan.
  10. Improve one component at a time and rerun across multiple public scenarios.
