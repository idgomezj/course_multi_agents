How to use, test, and review the challenge frontend

This guide explains every control, what the evaluation button runs, what the results mean, and a recommended testing workflow.

1. Team / case dropdown

Select the team whose public business case you want to test. The available teams come from the backend. Changing the team reloads that team's public scenarios.

2. Public scenario dropdown

Select the development scenario to evaluate. Each scenario changes the visible operating conditions, so the agent should solve the selected scenario instead of reusing one fixed plan.

3. Run public evaluation button

Runs the full public evaluation for the selected team and scenario:

Manager → Skills → RAG → PyTorch → Tools → Plan → Simulator → Evaluator

This is for development and review. It is not the hidden final evaluation.

4. Score cards

  • Operational: overall public business-result score.
  • Feasibility: whether hard operating constraints were respected.
  • Service: realized service against the scenario target.
  • Cost: cost performance relative to the public benchmark.
  • RAG: whether expected evidence was retrieved.
  • Skills / Tools: whether the intended skills and operational tools were actually used.

5. Scenario result and violations

Scenario result shows realized cost, benchmark cost, and cost gap. Constraint violations shows simulator findings that explain why a plan is feasible or infeasible.

6. Agent trace

Review tool calls in order, including inputs and outputs. Confirm the agent really used the expected architecture rather than only producing a plausible final answer.

  • Check that relevant Skills and RAG evidence were used.
  • Check PyTorch/model calls and operational data lookups.
  • Check cost and validation steps before the final plan.

7. Structured monthly plan

This is the final structured plan produced by the Manager. Review orders, actions, assumptions, and explanations together with the score cards and trace.

8. How to test changes

Change only one component at a time—model, RAG, Skill, prompt, or tool behavior—then rerun the same scenario. After that, repeat on multiple scenarios to make sure the improvement generalizes.

9. Recommended review workflow

  1. Select the team and one public scenario.
  2. Run the public evaluation.
  3. Check feasibility and service first.
  4. Review realized cost, benchmark, and cost gap.
  5. Review RAG and Skills/Tools scores.
  6. Inspect the Agent trace from first call to last call.
  7. Inspect the final structured plan.
  8. Modify one component and rerun the same scenario.
  9. Repeat across several scenarios before deciding the change is better.

10. Logs and deeper debugging

The frontend summarizes the run; server logs show the internal execution. Use the request X-Trace-Id to correlate events. Every structured log now also identifies the source file, line, and function; text logs display [filename.py:line:function].

Use those fields to jump directly from a failed event to the Python code that emitted it.
