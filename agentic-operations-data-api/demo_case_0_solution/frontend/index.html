How to use the Case 0 demo

Use this guide to understand the dropdowns, the two evaluation modes, the score cards, and how to review a run.

1. Scenario dropdown

Select one of the public Case 0 development scenarios:

  • T0-P01: balanced month.
  • T0-P02: supplier-risk trade-off.
  • T0-P03: promotion / demand increase.

Each scenario changes the business conditions the AI Manager must respond to.

2. Manager LLM dropdown

Select the LLM used only as the Manager/orchestrator. The same Case 0 data, PyTorch models, RAG, Skills, tools, simulator, and evaluator stay unchanged.

  • ready: the provider API key is configured.
  • API key missing: that provider cannot run until its key is added.

3. Evaluate published reference

This does not call an LLM. It loads the known worked reference plan for the selected scenario and sends it directly through the deterministic simulator/cost engine.

Use it first to understand what a feasible, high-quality reference result looks like and to verify the evaluator itself.

4. Run AI Manager end-to-end

This runs the real agentic workflow:

LLM Manager → Skills → RAG → PyTorch → Tools → Structured Plan → Simulator → Evaluator

The AI must solve the selected scenario independently. It does not load the published reference plan.

5. Runtime status badges

  • Data: Case 0 business data loaded.
  • RAG: RAG configuration is available.
  • Skills: number of available procedural Skills.
  • model_a.pt2 / model_b.pt2: trained PyTorch artifacts are present and ready.
  • LLM provider badges: whether each provider key is configured.

If a model says NOT TRAINED, run python demo_case_0_solution/train_models.py before testing the AI Manager.

6. How to read the score cards

  • Feasibility: whether the plan satisfies hard operational constraints.
  • Service: realized service level relative to the service target.
  • Total Cost: realized simulated operating cost.
  • Cost Score: how close the plan is to the public benchmark cost.
  • RAG: whether expected organizational evidence was retrieved.
  • Skills / Tools: whether the Manager used the procedural Skills, expected operational tools, cost/validation discipline, and an efficient workflow.

7. Cost breakdown and violations

Cost breakdown shows where the total cost came from. Compare purchase, production, holding, working-capital, overtime, expedite, changeover, stockout, lost-sales, and line-stop costs when present.

Violations shows simulator findings. Any critical violation makes the plan infeasible.

8. Evaluation breakdown

This explains exactly why the RAG and Skills/Tools scores were assigned, including:

  • Skill usage points;
  • expected operational tools used/missing;
  • calculate_plan_cost and validate_plan usage;
  • efficiency penalties and exact duplicate calls.

9. Agent tool trace

Review the tool calls in order. The trace answers questions such as:

  • Did the Manager inspect inventory and open POs?
  • Did it load Skills?
  • Did it retrieve RAG evidence?
  • Did it call PyTorch models?
  • Did it compare supplier/cost alternatives?
  • Did it validate the plan before finalizing?

10. Structured monthly plan

This is the final Pydantic-validated output generated by the AI Manager (or the reference plan in reference mode).

Review production orders, purchase orders, actions, assumptions, and explanation. A plan can be feasible and still be unnecessarily expensive.

11. Recommended testing workflow

  1. Select a scenario.
  2. Click Evaluate published reference and note the expected feasible/service/cost result.
  3. Select a configured Manager LLM.
  4. Click Run AI Manager end-to-end.
  5. Check feasibility and service first.
  6. Compare AI total cost with the benchmark/reference.
  7. Review RAG and Skills/Tools.
  8. Inspect the trace to see exactly what the agent did.
  9. Inspect the final plan.
  10. Repeat the same scenario with another LLM to compare orchestration behavior.
  11. Repeat T0-P01, T0-P02, and T0-P03 to verify scenario generalization.

12. Logs and deeper debugging

The UI is the high-level view. The server logs show the internal execution in detail. Each request receives an X-Trace-Id that can be used to correlate Manager, Skills, RAG, PyTorch, tool, simulator, and evaluator events.

Each structured log includes the source file, line, and function. Text logs show [filename.py:line:function], so you can jump directly from a runtime event to the code that emitted it.

See LOGGING.md for runtime observability and EVALUATION.md for the exact scoring rules.
