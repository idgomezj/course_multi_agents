Measured hardware vs. projected infrastructure

Measurement provenance

The benchmark ran on a GitHub Actions Linux runner (4 logical CPUs, 15.61 GiB host RAM), not on EC2.

Rules: 111,111.1 requests/s. ML: 1,484.8 requests/s. Pretrained: 37.3 requests/s.

100 requests/s were offered in a short in-process load test: the pretrained model completed 40%, with throughput 38.78/s. This is not a 1,000 req/s cluster validation.

EC2 instance selection and prices

Rules and ML: m7i.large (2 vCPU, 8 GiB) at $0.1008/h. Pretrained: c7i.xlarge (4 vCPU, 8 GiB) at $0.1785/h.

Each basic instance is assigned 30 GB of gp3 storage; each pretrained instance 50 GB, charged for a full month at $0.08/GB-month.

replicas = ceil(target RPS / (measured RPS × utilization))
active EC2 = replicas × price/hour × hours/day × days
storage = replicas × GB/instance × $/GB-month

Tokens, network, and unpriced components

Model tokens do not produce API charges

All three implementations execute locally. Provider per-token charges are $0. The pretrained model measured 107 NLI input tokens/message, across four candidate labels.

Monthly tokens: 92,448,000,000. Effective compute+storage cost is an internal infrastructure-per-token ratio, not a vendor tariff.

Network assumption

The reference benchmark measured only average JSON response bodies. At this workload, response payload egress is ~19–24 GB/month across approaches, before HTTP headers, TLS, retries, logging, and load-balancer traffic.

The baseline assumes the first 100 GB/month of outbound internet traffic is available to this account. Application load balancers, public IPv4, NAT, AWS logs, snapshots, support, inter-AZ transfer, and tax are excluded.

Engineering limitation

Capacity extrapolation—not a production guarantee. The runner had four logical CPUs; m7i.large has two vCPUs. Scaling from its observed throughput to EC2 is not directly validated. One ML instance and 39 pretrained instances are illustrative counts. A proper sizing decision requires a 30–60 minute sustained test at 1,000 requests/s, with real HTTP concurrency, on representative EC2 hosts. Cold-start, queueing, saturation, error rates and p95/p99 should be recorded.
